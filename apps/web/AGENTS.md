# Web (apps/web)

Read with the root AGENTS.md whenever you change anything under `apps/web`. Paths from the repo root.

## UI principles

- Every action is discoverable: visible labels, chevrons or action icons, deliberate hover, focus, selected, disabled, busy and error states; never hover-only or color-only.
- Frequent navigation is compact and flat, with no cards inside cards for switchers or lists. A page's own section list uses `components/ui/nav-list.tsx` in its on-surface variant: selection is one flat fill, hover a lighter fill; no outline, border, shadow or second background stacked on an item. Device and workspace selection has its own page; sidebar entries use forward arrows, not dropdowns. Restrained spacing, one surface boundary, a distinct selected fill or checkmark. Selected and hovered stay distinguishable side by side in both themes; never stack selection borders, inset bars, badges and heavy focus rings. Visual acceptance is separate from test success: inspect at normal scale in the full page, not only enlarged components.
- 侧边栏保持简洁：一个功能只占一个入口；在同类对象间切换（如切换助理）放在该页标题的下拉里，不在侧边栏另加一行或一个 tab。
- Browsing, selecting and managing are distinct. Browsing a device never changes the active location; commit device plus workspace together only after an explicit workspace choice succeeds, and cancel or failure keeps the context.
- One page per object. The Workspaces page (the sidebar location entry) lists every workspace grouped by device: Switch is the only action that changes the active location, adding a folder sits on its device group, rename and remove sit in the row menu with explicit destructive copy. Device pages manage machines (system, worker, accounts, skills, resources, settings), not workspaces, and link to the device's group.
- Customize shared or third-party UI only through public props, variants, slots, `className` or `style`, and style your own elements. Never reach into a component's private DOM or classes, add `!important`, or repair CSS with JS measurement. If the API is insufficient, extend the shared component's API (a prop or cva variant); lay out with grid/flex/min-width/wrapping utilities.
- One component system. The UI is built from `apps/web/src/components/ui`: Beautiful UI components (the look) and shadcn/ui components (Dialog, DropdownMenu, ContextMenu, Popover, Tooltip, Sonner, Select, Command, Input, Checkbox, Switch…, the interactive behaviour, on Radix) on Tailwind v4 over one token set (`styles/foundation.css`, `styles/tokens.css`). Features and shared widgets use those components plus Tailwind utilities for layout and spacing; they add no stylesheet and no second set of controls, and a page never styles its own buttons, inputs, menus, dialogs, badges, tabs or switches: extend the component with a variant or prop. Take Beautiful UI's visuals, but build menus, switches, popovers and dialogs on shadcn/Radix, never hand-rolled `<div role="menu">`. Replacing or adding a mature library is welcome when it fits better; customize any library only through its public API (props, variants, slots, `className`, theme tokens), never by overriding its internals. Never rebuild a native control (checkbox, switch, radio, input, textarea, select, button, menu, dialog) from `<div>`/`<span>`, bespoke borders, fake checkmarks or click handlers. Remove an npm dependency when nothing imports it any more (check with `knip`); never add site-only Beautiful UI dependencies such as `motion`.
- Hover, focus and press never move content: an interaction-only affordance floats out of flow (zero-size anchor plus `position: absolute`) or keeps its space at rest (`audit:state-layout` enforces it).
- Verify changed interactions in a real browser (keyboard, active/inactive, busy/error, light/dark, narrow) and record evidence and limitations.
- Device accounts and model providers (server API endpoints) are equal, discoverable choices, not buried sections; each runtime appears once, its details holding status and defaults; hints and fields get a deliberate vertical gap.
- Never claim an official account is valid online from cached identity alone: show the native configuration being read, distinguish local login from verified usage, never silently change the execution account. Official model pickers are selection-only and share controls with server connections.

## Where things live

Pointers, not specs; read the code first.

- New page and sidebar entry: `apps/web/src/lib/routes.ts` (view, path), `apps/web/src/app/navigation.ts` (`pageViews`, `navSections`), `App.tsx`, `app/use-app-route-sync.ts`, `app/view-error-policy.ts`, `components/ui/page-surface.tsx`; copy Connectors. Its body is `apps/web/src/features/<name>/`, public only via `index.ts`; features never import each other or `app/` (`apps/web/src/ARCHITECTURE.md`). Tabs: a route field in `lib/routes.ts` (`connectorTab` → `/connectors/<tab>`) drawn with `components/ui/segmented-control.tsx`.
- i18n: `apps/web/src/i18n/locales/{en,zh-CN}/<ns>.ts`, namespaces in `i18n/resources.ts`; both locales in one change, no literal copy in TSX. Document title: `app/use-document-title.ts`. Features open other pages only through `apps/web/src/lib/in-app-navigation.ts`.
- UI components in `apps/web/src/components/ui/` (extend their props and variants). The only CSS files are `src/styles/foundation.css` (Tailwind, Beautiful UI tokens, theme vocabulary) and `src/styles/tokens.css` (`--fdy-*` roles), plus the documented Streamdown hook sheet; `audit:component-system` fails on any other `.css` file, on a rule that selects an `fdy-*` class, and on utilities that bypass the theme (rules: `apps/web/src/ARCHITECTURE.md` › Styling).
- Web checks in `apps/web`: audits `scripts/audit-*.mjs` (all: `pnpm audit:ui`), `pnpm typecheck`, one test: `node --import ./test/register-bundler-resolve.mjs --test test/<f>.test.mjs`.
