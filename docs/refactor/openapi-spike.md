# Phase 6 spike: OpenAPI 3.1 as the single cross-language contract

> Adopted 2026-11-02: the contract is `contracts/evidence.openapi.yaml`, generated by
> `scripts/generate-evidence-models.mjs`. Since P2 S0 (2026-11-03) it is
> `contracts/models/evidence.yaml`, generated by `scripts/generate-contracts.mjs` with native Go
> unions; see [phase6-openapi-design.md](phase6-openapi-design.md). This is the spike's record; the spike's own files were removed after adoption, so paths below refer to them only historically.

Date: 2026-11-02. Scope: the evidence model (`packages/protocol/src/evidence.ts`, the hardest
case: `kind` unions, nested unions, inheritance, stored JSON). Nothing outside `contracts/`
was changed and nothing was committed. To reproduce every number below, run `contracts/scripts/run-spike.sh`
(it installs pinned tools under `/tmp/fdy-contracts-spike`, reads the evidence rows read-only, and
regenerates everything).

Pinned tools: openapi-typescript 7.13.0 (npm), oapi-codegen v2.8.2, ogen v1.24.0, oasdiff 1.35.0
(release binary, sha256-checked), Ajv 8.17.1, santhosh-tekuri/jsonschema v6.0.3, TypeScript 5.9.3.

## Result in one paragraph

OpenAPI 3.1 describes today's evidence JSON exactly, and the mature generators reproduce it.
The hand-written document matches today's generated JSON Schema in all 53 definitions,
including property order. openapi-typescript output is mutually assignable with `evidence.ts`,
with the same key sets, for every type and every union variant. oapi-codegen types re-encode all 42
round-trip inputs to JSON that is canonically identical to today's. With `x-order` they also
re-encode all 24 real stored rows byte for byte. The remaining byte differences are key order
only. oasdiff catches every synthetic breaking edit once the models are reachable from
operations and four checks are raised to ERR. **Recommendation: adopt OpenAPI 3.1 with
openapi-typescript (TS) and oapi-codegen (Go, models only); do not use ogen for stored data.
There is no reason to fall back to Protobuf.**

## 1. The document: `evidence.openapi.yaml`

The document is hand-written (1,362 lines, `components.schemas` only, `paths: {}`). I did not
generate it from TS: generating would keep TS as the source of truth, and the point of phase 6
is the reverse. To make hand-writing safe, `scripts/compare-schema.mjs` normalises the
OpenAPI into the dialect of today's `evidence-schema.json` (enum to anyOf of consts, union variants
and named nested objects inlined, allOf flattened) and diffs every definition, property order
included:

```
53 definitions compared, 0 mismatches; expected differences: {"EvidenceRecord":"additionalProperties: false only in today's schema"}
```

As a negative control, deleting one `minLength` and renaming one discriminator value produces 2
DIFF lines.

Modelling decisions, each forced by a tool or by today's JSON:

| Topic                  | Choice                                                                                                                               | Why                                                                                                                                                                                                                               |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Version                | 3.1.0                                                                                                                                | Needs `unevaluatedProperties` (closed records that use `allOf` inheritance) and `type: "null"`. All four tools accepted 3.1.                                                                                                      |
| Unions                 | `oneOf` of named variant schemas + `discriminator: {propertyName: kind, mapping}`; the variants use a single-value `enum` for `kind` | Every generator keys on this. Variant names follow `CheckConfigurationCommand`, `MaterialSelectorTextLines`, `VerifierIdentityAgent`.                                                                                             |
| `extends`              | `allOf: [EvidenceRecord, {...}]` + `unevaluatedProperties: false`                                                                    | JSON Schema cannot extend a closed object. So `EvidenceRecord` is open, and `ContractContent` is split into an open `ContractContentFields` plus a closed `ContractContent`. Nothing validates `EvidenceRecord` on its own today. |
| Anonymous object types | Named components with today's Go names (`MaterialTransformation`, `TargetSnapshotBuild`, …)                                          | oapi-codegen otherwise generates anonymous structs.                                                                                                                                                                               |
| `DateTime`, `Digest`   | `type: string` + `pattern`, **no** `format: date-time`                                                                               | oapi-codegen maps date-time to `time.Time`, which would re-format the stored strings.                                                                                                                                             |
| x, y, width, height    | `type: number, format: double`                                                                                                       | Without `format: double`, oapi-codegen generates `float32`.                                                                                                                                                                       |
| `JSONValue`            | Recursive `anyOf` + `x-go-type: any` + `x-go-type-skip-optional-pointer`                                                             | Same as today's Go type, `any`.                                                                                                                                                                                                   |
| Constraints            | The `minimum`/`maximum`/`minLength`/`pattern` rules of `refine()` in `generate-evidence-models.mjs`, written out explicitly          | Today these are name-based regexes. In the document they are visible per field.                                                                                                                                                   |

**Quirk carried over, needs a decision:** `refine()` turns every unnamed `number` into `integer`, so
today's `JSONValue` (used by `expectedJsonValues`, `CheckAssertion.expected/observed`) rejects `0.5`
although TS says `number`. The document mirrors this behaviour. ogen even enforces it at decode time
(see §3a). When adopting, change it to `type: number` unless the integer rule is intended.

Fixture validation straight from the document with mature validators (`scripts/validate-fixtures.mjs`
with Ajv, and `go/validate` with santhosh-tekuri/jsonschema v6) gives the same result in both
languages. 12/17 shared fixtures agree with the schema alone. The other 5 (selector edge bounds,
reversed lines, pointer escaping, two project-command rules) are business rules that
`validateNestedSelectors` / `ValidateContractContent` check by hand today, and they stay hand-written.

## 3. Comparison

### 3a. Go round trip (`go/roundtrip`)

Inputs: the 6 valid shared fixtures, 12 hand-written cases covering every union variant
(`fixtures/union-variants.json`, written in TS key order as the worker sends them), and 24 distinct
stored rows. The live `~/.foundry/server/foundry.db` has **0** `evidence_records`. The rows come from
read-only opens of `server/backups/foundry-20261010-*.db` and the `.tabs-/.timer-/.sec-stack` copies
(audit 7, material 6, contract 3, review 2, and one each of candidate, integration, decision,
evidence, input and verification). One `review_observation` row was skipped because it is not an
evidence.ts model. Each input is decoded and re-encoded with today's types (a copy of
`evidence_models_generated.go` + `marshalEvidenceUnion`, package `current`) and with each
candidate.

| Re-encoded by               | Byte-equal to today's encoding | Canonically equal (sorted keys) | Stored rows byte-equal |
| --------------------------- | ------------------------------ | ------------------------------- | ---------------------- |
| today's types vs input      | 32/42                          | —                               | 24/24                  |
| oapi-codegen (alphabetical) | 4/42                           | **42/42**                       | 0/24                   |
| oapi-codegen + x-order      | 33/42                          | **42/42**                       | **24/24**              |
| ogen                        | 30/42                          | **42/42**                       | 22/24                  |

Field names, `omitempty`, numbers and union shape are identical everywhere. All remaining byte
differences are key order:

- Today's union `MarshalJSON` round-trips through `map[string]any`, so union objects are stored with
  **sorted** keys (`{"args":…,"cwdRelativePath":…,"kind":"project_command",…}`). oapi-codegen keeps
  whatever bytes it decoded, so it reproduces stored rows exactly. It also builds new values through
  `From*`, which goes through `runtime.JSONMerge` and also sorts keys. The 9 non-matching cases are
  inputs that arrive in TS order: today's server re-sorts them and oapi-codegen keeps them as they
  are. ogen re-emits union keys in declaration order, which is why 2 stored rows differ.
- The digests (`evidenceDigest`, canonical sorted JSON) and `json_extract` do not depend on key order.

Differences in behaviour, beyond bytes (`go/ergonomics`):

1. **Nil slices in union variants.** Today `marshalEvidenceUnion` fills nil required arrays and maps
   of a union branch with `[]`/`{}`. oapi-codegen emits `null`. The same command check built with
   nil slices encodes to digest `fa2968ba64f0` today and `35e1d94b62fe` with oapi-codegen, and the
   oapi-codegen form fails the schema (null array). This applies to union variants only. Plain structs
   already emit `null` for nil required slices in both versions. No generator option changes it.
   Mitigation: build variants through small constructors, or validate every model before persisting
   (today the server validates only `ContractContent`, `RichContent` and `CarrierKind`).
2. **The zero union** encodes as `"selector":null`. Today a zero selector encodes as an object with an
   empty kind. Both are invalid, so neither version is safer here.
3. **Decoder strictness** (`TestDecodeStrictness`):

| Input                  | today      | oapi-codegen                  | ogen                                             |
| ---------------------- | ---------- | ----------------------------- | ------------------------------------------------ |
| float in JSONValue     | accepts    | accepts                       | **decode error**                                 |
| unknown field          | ignores    | ignores                       | **decode error** (`additionalProperties: false`) |
| missing required field | zero value | zero value                    | **decode error**                                 |
| unknown enum value     | accepts    | accepts (`Valid()` available) | decode ok, `Validate()` fails                    |

ogen's strictness breaks reading across a rolling update (old code reading rows that carry a new
field) and reading old rows. That, plus `Opt*` wrappers everywhere, a non-`encoding/json` codec
and 29k generated lines, rules ogen out for stored data.

### 3b. TS (`ts/assignability.ts`, `tsc` with `exactOptionalPropertyTypes`)

For every one of the 53 exported types, every variant of the 3 unions and the 9 formerly anonymous
nested objects, the check asserts that generated and hand-written types are assignable to each
other and have identical key sets. **It passes.** As negative controls, each synthetic edit in §3d
makes it fail with 4–15 errors.

### 3c. Union ergonomics

Go, today (one flat struct, every variant field is a nullable pointer, wrong-variant access compiles):

```go
switch cfg.Kind {
case "http":
    fmt.Println(*cfg.Method, *cfg.Path) // nil-check or panic
}
_ = cfg.Executable // compiles on an http check, silently nil
```

Go, oapi-codegen (plain fields per variant, but the switch is on `interface{}`):

```go
v, err := cfg.ValueByDiscriminator()
switch v := v.(type) {
case oapi.CheckConfigurationHTTP:
    fmt.Println(v.Method, v.Path)
case oapi.CheckConfigurationCommand, oapi.CheckConfigurationProjectCommand:
}
var s oapi.MaterialSelector
_ = s.FromMaterialSelectorTextLines(oapi.MaterialSelectorTextLines{Start: 3, End: 9}) // sets kind
// Pitfall: cfg.AsCheckConfigurationCommand() on an http check returns err == nil and an empty struct.
```

Go, ogen: `switch cfg.Type { case CheckConfigurationHttpCheckConfiguration: cfg.CheckConfigurationHttp.Method }`,
plus `Get*() (v, ok)`. This is the best typing of the three, but see §3a.

TS (`ts/ergonomics.ts`, compiles): narrowing on `kind` works exactly as with the hand-written
union, including a `never` exhaustiveness check and `@ts-expect-error` on cross-variant fields.

Migration size in Go is small: union fields are read in 9 places (`evidence_review.go`,
`evidence_registration.go`, `evidence_validation.go`), and union literals are built in 3.

### 3d. Breaking-change detection with oasdiff 1.35.0 (`scripts/oasdiff-cases.mjs`)

| Edit                                               | components only | with operations, default levels        | with `oasdiff-severity.txt` |
| -------------------------------------------------- | --------------- | -------------------------------------- | --------------------------- |
| add union variant (MaterialSelector `cell`)        | not reported    | ERR (`response-property-one-of-added`) | ERR                         |
| remove union variant (CheckConfiguration `http`)   | not reported    | ERR                                    | ERR                         |
| rename discriminator value (`project_command`)     | not reported    | ERR (enum value removed/added)         | ERR                         |
| make field optional (`AcceptanceCriterion.rubric`) | not reported    | WARN only                              | ERR                         |
| add required field (`ActorRef.tenantId`)           | not reported    | WARN only                              | ERR                         |
| add enum value (`Verdict`)                         | not reported    | WARN only                              | ERR                         |

oasdiff only checks schemas that operations reach. A components-only document always reports
"No breaking changes". For stored JSON, the same model is both written and read, so each model needs
to be reachable as both a request body and a response. The severity file raises 4 WARN checks to ERR,
because a rolling update has old and new code reading the same rows. Intended breaks are then
acknowledged in an ignore file (`--err-ignore`) in the PR that makes them.

## 4. Problems found

1. oapi-codegen sorts struct fields alphabetically. Keeping today's order needs `x-order` on every
   property (332 here), which is noisy to hand-maintain. Without it, stored JSON is canonically equal
   and only key order changes, which is harmless for `json_extract` and digests.
2. Union variants built with nil slices encode as `null` instead of `[]` (§3a.1). This is the only
   finding that changes digests.
3. oasdiff needs operations. A components-only document is invisible to it.
4. openapi-typescript's recursive `JSONValue` fails tsc without the `transform`/`inject` hook.
5. Ajv rejects `discriminator.mapping`. The spike ignores the keyword and lets `oneOf` decide, at the
   cost of worse error messages ("must have required property 'start'" for a bad page selector).
6. The structured-output schema sent to agents (`evidenceJSONSchema("VerificationResult")`) is
   derived today by rewriting `$ref`s. From OpenAPI it also needs `oneOf` turned into `anyOf` and
   `discriminator` dropped, because some providers' strict modes reject `oneOf`. That is a bundling
   step (e.g. `@apidevtools/json-schema-ref-parser`) plus a keyword rename, not a generator.
7. The `JSONValue` integer quirk (§1).
8. Environment: `/tmp/fdy-heavy-checks.lock` is held indefinitely by a scratch `foundry-server`
   (`/tmp/fdy-Wu12fh/foundry-scratch/web-css`, started 00:20) that inherited the lock fd. Other agents'
   `go test` runs are queued behind it. This spike ran its light steps under `systemd-run
MemoryMax` + `nice` without the lock.

## 5. Recommendation and adoption steps

Adopt **OpenAPI 3.1 + openapi-typescript + oapi-codegen (models only)** and keep Protobuf as an
unused fallback. Accept alphabetical key order: §3a shows canonical equality on every input, and
nothing in Foundry reads key order. If byte-stable payloads matter later, `x-order` (or an
OpenAPI Overlay that carries it) is a drop-in that was shown to give 24/24.

1. **Source.** Move `contracts/evidence.openapi.yaml` to `packages/contracts/` (or keep
   `contracts/`) and add real operations for the evidence REST routes. Until those exist, add one
   `x-storage` operation per stored model (request + response) so oasdiff sees the models.
2. **Replace `scripts/generate-evidence-models.mjs`:**
   - TS: openapi-typescript (devDependency of `packages/protocol`, pinned) generates
     `packages/protocol/src/evidence.gen.ts` with `--root-types --root-types-no-schema-prefix` through
     the 20-line `gen-ts.mjs` hook. `evidence.ts` becomes a re-export. Prettier runs as part of the
     generate command, so `--check` and `pnpm format` stop disagreeing (the cause of today's stale
     `--check`).
   - Go: oapi-codegen, pinned with a Go 1.24+ `tool` directive in `apps/server/go.mod` (`go tool
oapi-codegen`), generates `store/evidence_models_generated.go` with the §2 config. Rewrite the
     12 union call sites to `ValueByDiscriminator`/`From*`. Delete `marshalEvidenceUnion`. Add
     constructors or validate-before-persist for union variants (§3a.1).
   - Validation: delete both `evidence-schema.json` copies and the two hand-written schema walkers
     (`validateWire`, `evidence-validation.ts` schema part). Validate from the OpenAPI components with
     santhosh-tekuri/jsonschema v6 (Go) and Ajv (TS). Both were shown to give identical results on the
     fixtures. Keep the business rules (`validateNestedSelectors`, `ValidateContractContent`) only on
     the server, and give the web/worker a dry-run endpoint (phase 6 principle 2).
   - `docs/evidence-and-verify-v1-fields.md`: drop it (the YAML is the field list) or render it with
     a doc tool (Redocly).
3. **Daemon WebSocket (C1).** Describe each payload as a component. Describe the traffic as two
   unions, `ServerToWorkerMessage` and `WorkerToServerMessage`. Each is a `oneOf` of
   `{type: enum[<name>], id?, error?, payload: <Payload>}` with `discriminator: type`, so the 141 type
   names become enum values instead of hand-copied constants. TS gets a discriminated union, which
   lets `dispatch.ts` narrow on `type`. Go keeps `wsEnvelope{Payload json.RawMessage}` for dispatch
   and uses the generated payload structs (the existing `wsEnvelope` order is already alphabetical).
   Also describe the registration payload (`store.DaemonRegistration`, no TS type today) and the
   capability strings as enums. For oasdiff, expose each direction as one synthetic operation tagged
   `x-transport: websocket`.
4. **`audit-contract.mjs`.** For every migrated area, checks 1, 2 and 4 (name and field parity) drop
   out, because both sides are generated. Shrink `tsDtoPaths`, `daemonPayloadGoNames`,
   `daemonPayloadKnownDrift` as areas move, and delete the script when they are empty. Check 3 (the
   browser-event literal ban) stays until C4 migrates.
5. **CI** (`scripts/check-changed.sh` when `contracts/**` or a generated file changes, and `pnpm verify`):
   (a) regenerate TS and Go into a temp dir and diff against the committed files;
   (b) `oasdiff breaking <merge-base spec> <spec> --severity-levels oasdiff-severity.txt --fail-on ERR`
   with an `--err-ignore` file for acknowledged breaks;
   (c) the shared fixtures validated by Ajv and jsonschema v6;
   (d) during the transition, `ts/assignability.ts` against any hand-written type that is still kept.
6. **Order.** Migrate evidence first (it replaces an in-house generator and has fixtures), then the daemon
   WebSocket payloads, then the browser REST DTOs and the SSE payloads.
