## 0. 结论

- **Worker 与 Web 的中层收拢基本完成**：Worker 收进 `W/platform/`（原子写、路径包含、单飞、按 key 串行、退避、待回复关联、脱敏），顶层只剩 3 个入口文件，模块边界有审计；Web 的 HTTP 全部收回 `api/`，样式按模块就近存放，`features/chat` 分了子目录。
- **Go 侧的公共原语一项都没做**（阶段 5 Go 部分）：截断 helper 15 个、4 种语义；手写 UUIDv4/v7（`google/uuid` 已经是依赖）；`firstNonEmpty` 4 份；只增不减的 keyed mutex 3 份。`httpapi` 仍有 3.78 万行、175 个文件，没有按领域拆包。
- **跨语言规则大多仍在两端各写一份**。只有证据模型改成以 OpenAPI 为唯一来源；证据的业务规则仍是 Go/TS 两份。会话来源、活跃状态集合、转录标签、能力字符串、HTTP 错误码、cron、上下文窗口上下限都仍在两端手写。**已经出现一个由此造成的实际缺陷**：Worker 从 2026-10-16 起把 Codex 回合结束标签写成 `"Codex finished"`，Go 的用量回填和 Web 的预览识别仍然只认 `"Codex SDK finished"`。
- **遗留代码还有清单漏掉的几条完整链路**：注册里恒为空的 `skills` 一路通到 `skills` 表、`GET /api/skills` 和 `FoundryData.skills`；"Foundry 开始记录用量之前"的用量回填；`?access_token=`；MCP 旧参数名。
- **文档（阶段 8）没有开始**，并且有几处会直接误导：`docs/architecture-modules.md`、`CONTEXT.md`、`B/ARCHITECTURE.md`、`docs/evidence-and-verify-v1.md`，plan 和清单自己的状态也已过时。
- 规模几乎没变：Server 非测试代码 10.6 万 → 10.5 万行，Worker 7.6 万 → 7.4 万，Web 9.1 万 → 9.0 万。这几轮的主要成果是把代码搬进正确的位置，减少的重复不多。
