# Cross-cutting infrastructure and component contracts

Scope: infrastructure primitives, inter-component contracts, logic implemented in both Go and TS.
Source of truth: code at HEAD `615b51d7` (tree clean when read). Paths from repo root. `file:line` points at the definition.
Sizes (non-test): server Go `apps/server/internal` ≈ 104k LOC (httpapi 47.4k, sqlitestore 25.6k, store 8.7k); worker TS `packages/worker/src` 75.6k; web TS/TSX `apps/web/src` 104.1k; protocol TS `packages/protocol/src` 8.5k (+ 2,668-line generated `evidence-schema.json`).

There is no shared "infra" package on either side: Go has none of its own (helpers live in `httpapi` and are re-written per package); worker has three small grab-bags (`utils.ts` 77, `json-values.ts` 40, `paths.ts` 25) plus single-purpose modules; web has `src/lib/*` and `src/api/http.ts`; protocol is types + a few pure functions.

## Observations

**Scattered (many copies, no home)**

- Path containment: 1 Go helper + 10 inline; worker 1 helper (`paths.ts`) + 8 local functions + 17 inline checks with at least four different semantics (`startsWith("..")` rejects names like `..foo`; `paths.ts` checks `"../"` only).
- Atomic writes: `storage.ts writeFileAtomic` (88 callers) coexists with 3 private copies (`evidence-store.ts:64`, `knowledge/context-patches.ts:72`, `knowledge/files.ts:107`) and ~20 raw `renameSync` sites.
- Single-flight: worker repeats the module-level `pending` Map idiom 6×; web has `lib/single-flight.ts`; Go has 3 ad-hoc in-flight maps and no `singleflight`.
- Per-key serialization: 6 hand-rolled promise chains in worker while `ConcurrentTaskScheduler` (per-key, limit) has one user.
- Request/response correlation: 5 worker correlators (execution host, host-child, codex JSON-RPC, MCP stdio, foundry client) + Go `daemonRPC`, each with its own ids, timeouts and disconnect semantics; 9 JSONL readers.
- Backoff: 14 schedules (6 worker, 5 web, 3 Go), no helper; jitter rules differ.
- Truncation: Go has 7 rune-cut functions with 3 different length/ellipsis results; worker ~10; web 2.
- Redaction: 4 rule sets (Go 1, worker 3) with different token thresholds and markers.
- Env reading: Go centralizes it in `config.go` with injected `getenv`; worker reads `process.env` in ~40 files (~60 names, timing knobs inline).
- Worker state layout: ~40 file/dir names spelled at 68 call sites; `.foundry/…` workspace layout spelled in ~15 worker files and 3 Go files.
- Logging: Go `log.Printf` ×210 with free-form prefixes; worker `console.*` ×165; no levels or structure; redaction only on diagnostics export.
- HTTP clients in Go: 4 use `http.DefaultClient` (no timeout), 4 build their own.
- Error text: worker `errorMessage` helper exists, inline pattern still repeated 20× (web 45×); Go matches error text with `strings.Contains` 22×; web regex-matches server/worker message text in 16 places.

**Lumped (one file carrying several concerns)**

- `worker/src/utils.ts` mixes fs read, id slug, byte label, CLI option parsing, sleep, child stdin with agent-process stop (imports `agent-processes.ts`), error message.
- `worker/src/transport.ts` (1,016) holds outbox, acks, piecing, pacing, coalescing, server-feature parsing and WS send helpers.
- `httpapi/http_responses.go` mixes status mapping, device error phrasing, ETag JSON caching and DB-busy responses; `httpapi` (47k LOC, 380 files) holds all Go infra helpers, so other Go packages (`feishu`, `resources`, `workspacedigest`, `personalagent`) rewrite their own truncation/ids/clients.
- `workspace-ops.ts` holds daemon registration, chat sync, and the daemon capability list.

**Leaky (contract knowledge outside its definer)**

- Capability/feature names (~50) are spelled as literals across ~25 Go files, the worker list, the execution-host list and protocol constants; unaudited, although they gate dispatch (`session_dispatch.go:46`, `personal_agent_inbox.go:170`).
- HTTP error `code` strings cross Go → web by hand; worker refusal codes are re-translated by Go (`sensitive` → `file_sensitive`).
- Worker error strings flow verbatim as Go errors (`daemon_wire.go:541`) to web, which strips `Error: ` (`api/http.ts:229`) and regex-matches text.
- Go knows worker process-label strings, including legacy Chinese ones (`helper_failure.go:155`).
- Web hard-codes the worker install path `~/.foundry/bin/foundry-worker` (`lib/worker-commands.ts:7`) and personal-agent caps/words.
- The registration payload (largest daemon payload) has a Go struct but no TS interface.

**Contract mechanisms in use (evidence for "define once" options)**

- Name/field parity audit (`audit-contract.mjs`): daemon types, daemon payloads, REST DTOs, SSE vocabulary. Covers names only, not types.
- Shared JSON fixtures read by Go and TS tests: browser events, evidence, provider endpoint, subagent responses (4 pairs). Cron, session schedule, redaction, path rules, id grammar have none.
- Codegen from TS: evidence only (`generate-evidence-models.mjs`); its `--check` is unwired and conflicts with Prettier formatting of the outputs.
- Single embedded artifact consumed across languages: `mcp_tools.json` (read by Go at build, by worker tests from the server tree); builtin foundry skill copied byte-for-byte and test-checked.
- Untyped internal protocols: execution-host socket (`protocol: 1`, `any`), host-child JSONL, evidence RPC (TS union vs Go `map[string]any`), daemon REST bodies.

**Extraction candidates (named by evidence, not ranked)**

- Worker: one path-containment helper (replace the 8 local functions and 17 inline checks), one atomic-write (merge the 3 private copies into `storage.ts`), one keyed single-flight/serial queue (6 + 6 sites), one JSONL request/response channel (5 correlators), one backoff helper, one redaction rule set shared by `redactSecrets`/transcript/diagnostics, a state-layout registry for `foundryStatePath` names, a worker config module for `FOUNDRY_*` env.
- Go: a small shared package for rune truncation, id minting, outbound `http.Client` construction (timeouts), and backoff; currently copied into `feishu`, `feishuevents`, `resources`, `workspacedigest`, `personalagent`, `skillrepo`, `skilltools`.
- Cross-language, as data (fixtures or generated constants): capability/feature names, HTTP error codes, process labels, context-window bounds, personal-agent caps/words, clarification tool set, id grammar, state-root rule, `.foundry/` workspace layout, cron grammar cases, session-schedule cases, redaction cases.
- Contract typing: TS interface for the daemon registration payload; typed Go structs for evidence RPC requests (the TS union exists); a declared message type for the execution-host socket.
