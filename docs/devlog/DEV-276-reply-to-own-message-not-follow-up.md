# DEV-276 本人回复自己的消息不再被当成续聊交给助理

2026-11-17。本人截图反馈：在与同事的私聊里，本人引用自己刚发的「AutoFix 饼图状态定义」文档，写「你统一看看这个，重点是 状态枚举值 和 tag->状态 的映射关系」（说给对方听），却被交给了助理（sess_1794902398667612761）。

状态：已修复；已部署 dev（2026-11-17）；待本人验收；已合入 main（PR #274）。

## 事实与根因

- 投递记录 `dlv_7837350ea20473d6b4cabe1c`：rule `follow_up`，事实行 `quote (since 2026-11-17T07:59:49.835Z) by "邓灿文" …, the person`；信封 `replyTo` 指向本人 12:00:11 手动发的文档消息（该消息本身 `no_rule_matched`，不是助理写的），`replyToMe: true`。
- `channels/followup.go` 把 OpenLark 的 `replyToMe` 当作「回复了助理的消息」。但通道用的是本人的账号：`replyToMe` 的含义是「回复了这个账号发的任何消息」，本人自己手写的消息也算。同一私聊上午 07:59 用过 `/ai`，会话绑定仍在，于是本人对同事说的话成了续聊。
- Foundry 自己知道哪些消息是助理写的：网关为助理会话（及其 helper）记录的 `createdMessageId`（`messageChannelOwnWrites`，DEV-233/243）。

## 修复

- `followUpIndex` 带上本批次的 `ownWrites`；「回复助理」改为 `replyTo` 指向助理写过的消息，不再看来源的 `replyToMe`。引用已交给助理的消息（`quotes`）与话题续聊不变。
- 扩展描述里的 `attributes.replyToMe` 不改（规则过滤仍可用它），只是续聊不再依赖它。
- 当时那一轮由编排者取消；网关审计显示它只读了两次消息上下文，没有任何写入。

## 检查

- `go test ./internal/channels/...` 在 byte-dev-sg 通过（新增回归：本人以 `replyToMe` 回复自己的消息 → 不续聊；回复助理写的消息 → 续聊）。

## 验收步骤

1. 在某私聊里先 `/ai` 让助理回一条；然后引用助理那条回复再说一句：应作为续聊交给助理。
2. 在同一私聊里引用自己手发的一条消息说话（不带 `/ai`）：不应交给助理，消息上不出现处理中的表情。
