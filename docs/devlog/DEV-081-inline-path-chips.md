## 问题 1：悬停或聚焦路径时，后面的文字左右跳动

用户反馈（2026-10-29，截图 `.foundry/attachments/20261029/att_dmh5pbp1mqrg/att_dmh5oglwojd1_0_image.png`）：复制图标直接排在行内路径后面，鼠标移入移出时，后面的内容来回跳动。

### 原因

DEV-065 给回答里的路径加了复制按钮：平时 `width: 0`，`:hover` / `:focus-within` 时变成 `width: 22px; margin-left: 2px`。按钮在行内文字流里，变宽就把同一行后面的文字往右推，离开时再拉回。这一设计本身是错的。审计当时没有任何规则检查“状态变化改变尺寸”。

### 调研与选择

| 产品                     | 行内路径/代码的复制入口                | 是否挤动正文 |
| ------------------------ | -------------------------------------- | ------------ |
| GitHub 代码块            | 悬停时右上角浮出复制按钮，覆盖在内容上 | 否           |
| VS Code 悬停             | 悬停卡片（浮层）里放操作               | 否           |
| Slack 消息               | 悬停时浮出工具条，覆盖在消息上         | 否           |
| Notion / Linear 行内链接 | 悬停卡片或右键菜单                     | 否           |

共同点：操作入口浮在内容之上，不占文字流。可选方案有三种：Portal 浮层（Radix Popover），放进悬停卡片，或右键菜单。浮层和悬停卡片都放在 Portal 里，Tab 顺序里够不到；右键菜单则不可发现（AGENTS.md）。最后选的是“零宽锚点 + 绝对定位浮动按钮”：

- 路径按钮后面放一个 `width: 0; height: 0` 的 `inline-block` 锚点（`.fdy-chat-file-reference-anchor`），复制按钮 `position: absolute` 从锚点浮出，覆盖在后续文字之上（不透明表面、细边框、阴影，悬停时也保持不透明）。显示和隐藏只改 `opacity` 与 `pointer-events`，不改任何尺寸。
- 按钮仍在 DOM 里紧跟路径：Tab 先到路径、再到复制按钮，读屏读到 “Copy <完整路径>”。路径用键盘聚焦（`:has(:focus-visible)`）时按钮立即出现；鼠标点击路径不会让按钮常驻。
- 显示延迟 80 ms，隐藏延迟 160 ms；按钮左侧有一条 5 px 的透明 `::before` 桥，鼠标从路径移向按钮时不会消失。
- 触屏（`@media (hover: none)`）没有悬停：锚点固定占 28 px，按钮常显。这块空间从渲染开始就在，交互时不变化，也不会挤动。
- 文件面板的路径行保持常显的复制按钮（固定占位，不涉及）。
- 只用 `CopyButton`/`Button` 原语和自有样式表，没有 JS 测量，没有 `!important`。
- 自验时发现一个问题：`.fdy-button` 带 `max-width: 100%`，零宽锚点里按钮被压成 2 px 宽，只剩图标，看不出是按钮。已加 `max-width: none`，测试也断言按钮为 24×24。

### 防止复发

- `apps/web/scripts/audit-state-layout.mjs`（`pnpm audit:state-layout`，已加入 `audit:ui`）：任何 `:hover`、`:focus`、`:focus-within`、`:focus-visible`、`:active`（含 `:has(...)` 形式）规则，不得设置会改变排版的属性（宽度、内外边距、边框宽度、字号/字重、`display`、`position`、`flex`、`gap` 等）。两种情况放行，因为不会挤动内容：
  - 同一属性在无状态规则里已经是同一个值；
  - 该元素静止时就是 `absolute`/`fixed`。

  现存样式零违规。用 DEV-065 的旧规则做反例，会报 `width: 22px; margin-left: 2px`（`test/audit-state-layout.test.mjs`）。

- `apps/web/test/inline-affordance-shift.test.mjs`：真实浏览器测试。用真实的回答渲染结果和应用的全部样式表，在 Chromium 中逐个悬停路径、慢速移到复制按钮、模拟已复制、移开、Tab 聚焦路径和复制按钮，比较回答里每个文字框的位置与宽度，必须与静止时完全相同；同时断言按钮 24×24、能接住指针。宽度为 1280 light 与 390 dark，另跑一组触屏。找不到 playwright-core 或 Chromium 时跳过（可用 `FOUNDRY_TEST_PLAYWRIGHT_CORE` / `FOUNDRY_TEST_CHROME` 指定）。用旧样式运行时失败：第一个路径悬停后，后续文字 x 右移 24 px。
- AGENTS.md 的 UI 原则补了一条：悬停、聚焦、按下都不得移动内容。

## 问题 2：路径 `正方_读万卷书/` 打开后报 ENOENT

用户反馈：回答里的 `正方_读万卷书/` 打开 Source 面板后报 `ENOENT … lstat '<workspace>/正方_读万卷书'`。真实路径是 `<workspace>/市直赛辩论_读万卷书VS行万里路/正方_读万卷书`。同一列表里的 `.docx` 没有成为链接。

### 原因（只读核对了该会话的回答和文件账本）

回答的结构是：先在一段里写 “放在新建的子文件夹 `市直赛辩论_读万卷书VS行万里路/` 里”，接着一段只有粗体的 “**文件夹结构**”，然后是列表，列表里的条目只写名字（`00_备赛总览（先看这个）.docx`、`正方_读万卷书/` …）。这些 `.docx` 由会话里的 Python 脚本生成，不在会话的文件账本里。

1. Worker 回合结束时验证路径（`resolveFileReferences`）：
   - 段落里的文件夹只传给紧跟它的列表，中间隔了一段 “文件夹结构”，传递就断了。于是列表里的名字按工作区根目录解析，找不到，`.docx` 没有成为引用。
   - 文件夹必须“装着账本里的文件”才算引用。脚本写的文件不在账本里，所以连真实存在的 `市直赛辩论_读万卷书VS行万里路/` 也不算。
2. Web 端在没有已验证引用时，会按形状猜测并直接链接（DEV-055 Phase 1 的 `workspacePathReference`），从不检查是否存在。单个名字带 `/` 的被当作目录，拼到工作区根目录下，于是出现了不存在的 `<workspace>/正方_读万卷书`。不带目录的文件名只认一小组扩展名，`.docx` 不在其中，所以文件没成为链接、文件夹却成了链接。

### 修复

- 规则一：路径按钮只链接设备验证过、确实存在的路径，否则保持为普通的可复制文本（行内 code）。Web 删除了工作区路径的形状猜测（`workspacePathReference` 及其规则），只认 Worker 回合结束时给出的 `fileReferences`。
  - 例外：设备所有者在工作区外的文件仍按形状链接（DEV-055 Phase 2，只对所有者，打开时由设备检查并给出“不存在”等状态）。原因是 Worker 出于安全考虑不验证这类文件，去掉会让 DEV-055 的原始需求失效。工作区内的绝对路径不再走这条猜测（`devicePathReference(text, root)`）。
- 规则二：相对名字按来源依次解析（Worker `matchesOf` / `locate`），每一步只在恰好一个存在的匹配时链接，多个匹配视为有歧义，不链接，也不再往下找：
  1. 会话账本里以它结尾的路径（文件，或账本文件所在的文件夹）；
  2. 回答中此前提到的文件夹（同一段里后面提到的也算，例如 “`a.md` 在 `docs/` 里”）；
  3. 工作区（会话的 cwd）。
- 规则三：文件和文件夹一视同仁。工作区内的文件夹只要存在就能链接，不再要求装着账本文件。工作区外的文件夹仍要求装着已记录的文件；工作区根目录、家目录和临时根目录本身仍不链接。
- 打开文件夹时：如果它装着本会话的文件，照旧在右侧面板筛出这些文件；如果没有（例如脚本生成的），就在工作区浏览器中打开这个目录，从设备读取（`use-chat-context-panel.ts`）。

## 验收步骤

1. 在任一回答里有路径的聊天中，把鼠标移到路径上、移到浮出的复制按钮上、再移开。预期：后面的文字一点都不动；复制按钮浮在路径右侧，有边框和阴影；点击后显示对勾并弹出 “Copied”，粘贴得到完整路径。
2. 用 Tab 聚焦路径，再按一次 Tab。预期：聚焦路径时按钮出现，第二次 Tab 落到复制按钮（读屏：“Copy <完整路径>”），Enter 复制；全程文字不动。
3. 手机（或浏览器触屏模拟）上，复制按钮一直显示在路径后面，点按复制，文字不动。
4. 新的回答（需要 Worker 更新到包含本改动的版本）如果先写 “放在 `某文件夹/` 里”，再隔一段说明，然后列出只写名字的子文件夹和文件：这些名字都应成为链接；点击子文件夹，应在工作区浏览器中打开正确的目录。不存在的名字保持为普通文字，可以选中复制。
5. 旧回答（包括报告中的那一条）：没有经过设备验证的名字现在显示为普通文字，不再是会报 ENOENT 的链接。
