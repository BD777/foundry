# DEV-039 Worker 错误诊断与恢复建议

2026-10-23，用户要求改善执行主机停止的提示，并把错误检测和建议封装成高内聚、低耦合模块。来源会话：`sess_1792725388448975946`；事故会话：`sess_1792554454421184081`。

## 事故证据与边界

事故发生在 macbook。北京时间 10 月 23 日 11:47:59 审查子会话写 outbox 报 ENOSPC；主会话 11:50 磁盘约有 10 GiB，12:03:57 剩 1.9 GiB，12:06:24 剩 971 MiB，12:07:25 后台库存采集报 ENOSPC，12:08:05 被标记为执行主机停止。执行主机在启动时将上次仍 active 的 claim 结束为通用错误；该文本说明恢复结果，不证明服务退出原因。

本轮不把磁盘告警升级为“崩溃已确诊”。Mac execution-host 两份日志为空，尚无最终退出异常栈；磁盘增长来源、低磁盘保护及 macOS 启动器日志修复另行处理。本轮不清理磁盘、不自动重试失败任务、不强制重启活动宿主。

## 模块边界

- `packages/protocol/src/worker-failure.ts`：无 I/O 的统一分类与恢复策略；版本化 code/inputId、故障位置、恢复建议标识。支持执行主机停止、ENOSPC、明确模型限流、技能准备超时、轮次上限、未知错误。新版本或未知 code 安全回退；不把一般 HTTP 429 猜成模型限流。
- `packages/worker/src/worker-failure.ts`：唯一新增上报边界，脱敏原始错误，先发绑定 inputId 的诊断事件，再发兼容旧客户端的终态 error。接入普通 session 执行异常、无宿主 daemon 调度异常、宿主调度外层异常和重启 claim 恢复；其他业务专用异常仍按原通道处理，可继续接入此模块。
- Server 只透传和持久化事件的 `workerFailure` 元数据，复用原有 JSON 存储，无数据库迁移。旧 Worker 无元数据仍可使用。
- `apps/web/src/features/chat/chat-failure.ts`：前端适配，使用同一分类策略兼容旧记录，解析当前设备名及本轮诊断。渲染组件只接收已翻译的展示数据，不识别错误字符串、不执行修复命令。
- 对宿主中断，仅接受本轮时间范围内、特定 Worker `Notice` 的 ENOSPC 警告作为“中断前观察”，明确表示未确认因果。用户/模型正文、工具输出、旧轮次、完成后的告警均不参与诊断；结构化结果必须匹配当前 inputId 和终态原文。
