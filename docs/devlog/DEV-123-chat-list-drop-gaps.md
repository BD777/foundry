## 问题

2026-11-05 本人反馈：侧边 Chats 列表拖动会话、松手时偶尔回到原位，没有移动成功。截图中列表按分组缩进显示。

## 根因

HTML5 拖放按松手前最后一次 `dragover` 是否 `preventDefault()` 决定接受与否。`use-chat-list-drag.ts` 只在指针下方能找到 `[data-chat-drop]` 元素时才接受，而列表里有几处不属于任何放置目标：

- 分组之间 6px（`section` 的 `mb-1.5`）；
- 组内每行左侧 12px 缩进（内容区的 `ml-3`，属于 `section`）；
- 列表左右各 10px、底部 12px 内边距（`viewportClassName="px-2.5 pb-3"`），以及最后一项下方的空白。

在这些位置松手，浏览器取消拖放并把行动画送回原处，`drop` 不触发、也不发保存请求。指针划过时插入线只闪一下，所以表现为偶发；“拖到组尾 / 拖进下一组 / 拖到最底下”最容易落在缝里。

排除：布局保存 CAS 冲突会先移动再跳回并显示“更改未能确认保存……”，截图无此提示，服务端日志也没有布局保存失败；拖动中途被禁用只发生在加载、出错、删除分组时。冲突时直接丢弃改动、没有在新版本上重做，这是另一个隐患，本项未改。

## 修复

列表中拖动本列表的会话时，每次 `dragover` 都接受；放置位置只按指针高度计算（`chatDropTarget`）：候选为最内层可见的 `[data-chat-drop]`（行、分组标题、“未分组”标题、空分组）。落在行上按中线分前后；落在标题上进入该组；落在缝或列表下方，归到上方最近的位置之后。`drop` 用自己的坐标重新计算，不依赖 `dragover` 留下的状态。被折叠分组里隐藏的行高度为 0，不参与计算。

列表右缘 4px 是列表宽度拖拽手柄（`role=separator`），不是列表的一部分，不改。

## 人工验收

在 dev 的 Chats 列表（至少两个分组）：

1. 把一条会话拖到两个分组之间的空隙松手：它成为上一组的最后一条，不弹回。
2. 拖到组内行左侧竖线附近的缩进处松手：按该行上半 / 下半落在它前或后。
3. 拖到列表最下方空白处松手：进入“未分组”。
4. 拖动途中插入线一直可见，松手位置与插入线一致。
5. 落在行上、拖到分组标题上的行为与以前相同。
