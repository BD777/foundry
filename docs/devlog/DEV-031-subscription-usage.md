# DEV-031 · Subscription account usage in the chat side panel

Status: implemented, deployed and Agent-accepted for the verified scope below. The original quota implementation, compact layout and alignment fix merged through PR138; post-merge and final main CI passed. Claude availability/freshness limitations remain unchanged.

The request is to show the selected official subscription account's quota in the right panel. It is account-wide usage, distinct from the conversation's Context token meter. API-key and compatible endpoint profiles do not inherit subscription quotas.

## Native capability evidence (2026-10-21)

- Installed Codex CLI **0.163.0**: generated `app-server generate-json-schema` confirms `account/rateLimits/read` and the multi-bucket `rateLimitsByLimitId` response. The legacy `rateLimits` is a single-bucket fallback. Native windows supply percentage used, duration and reset time; no fixed 7-day assumption. [Official app-server reference](https://learn.chatgpt.com/docs/app-server#6-rate-limits-chatgpt).
- Installed Claude Code **2.1.295**, Agent SDK **0.3.201**: bundled `sdk.d.ts` exposes `usage_EXPERIMENTAL_MAY_CHANGE_DO_NOT_RELY_ON_THIS_API_YET()`, a `get_usage` control request with subscription windows, model-scoped windows and enabled extra usage. The method is explicitly experimental. Capability errors degrade without disrupting a conversation. The older claim that the SDK never exposes quota is obsolete. [Official CLI usage documentation](https://code.claude.com/docs/en/costs#using-the-usage-command) documents account plan bars separately from session cost; interface/version evidence comes from the installed SDK declaration.
- Real local Codex metadata-only inspection returned a verified subscription with a 10,080-minute window, a numerical percentage and reset timestamp. No prompt/turn was sent. The report deliberately omits the account identity and private quota values.
- Real no-prompt Claude SDK probe successfully invoked the control method, returning `rate_limits_available=false`, no plan/windows, zero session cost and zero model-usage entries. The current Linux login could not be established by the normal account inspection. This verifies the control capability and unavailable path, **not** a real Claude subscription percentage. A second real probe on the Mac confirmed an official local subscription and `rate_limits_available=true`, but returned no windows. The deployed adapter therefore reports unavailable quota and retains no invented values.

Installed CLI source inspection additionally confirmed that `get_usage` may project seeded/last-known limits while omitting their original observation time. Claude results carry `quotaMayBeCached`; they retain local-login status rather than claiming online verification, and the side panel labels them as potentially cached. `checkedAt` is the time Foundry read the native observation, not an invented provider timestamp.

## Implementation

- Extend the existing native account inspection DTO with authentication mode, quota availability/reason, native login generation, stable window identifiers and optional percentage. Missing values remain unknown, never zero. Native provider adapters share one window display.
- Reuse the owner-only device inspection route. Sidebar requests must identify the actual native profile and generation; compatible endpoints, alternate source paths and changed generations are rejected. Worker checks generation before and after reads, deduplicates in-flight reads, and keeps successful observations for 60 seconds per native identity.
- Codex inspection uses existing isolated app-server lifecycle and explicit `allowRefresh=false`; quota reads cannot request native token renewal. Inference callers retain the existing default. Claude uses a no-prompt SDK stream in an ephemeral native operation with tools/plugins/MCP disabled and guarded login renewal. Only quota fields leave the worker; session costs/behavior summaries are discarded.
- The panel shows account-wide scope, used percentage, native durations and reset times; more than two windows expand on demand. Manual refresh is visible. Focus and conversation-state transitions may refresh after TTL; the staleness timer never starts a CLI. Offline/error/stale reads are labelled; permission/identity conflicts discard the old result. Device account inspection also partitions view memory by login generation.
- Native usage is never written into shared workspace/session events or persisted account-wide caches. Only the owning person's request receives it. No browser profile/cookies or private OAuth endpoint is used.

## Acceptance and limitations

Open a chat with an owned device's official subscription profile and expand its right panel. Usage should identify account scope beneath Context and display only native-reported windows. Select an API-key/gateway profile: no subscription Usage. Refresh/expand with keyboard; disconnecting a device should label the old observation.

Claude's experimental method may be absent or unable to expose quota for a given login/version. No fabricated percentage or model request is used to fill that gap.
