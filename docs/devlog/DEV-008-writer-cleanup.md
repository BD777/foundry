状态：2026-10-20 按用户显式委托，对已验证的 writer 退出清理修复准出归档。后续整合与 DEV-024 已覆盖真实锁、退出及同线程重试；实际部署证据和未重演原业务边界见文末及 [DEV-025](DEV-025-release-closure.md)。

## 问题、修复与已有证据

Codex 失败后残留原生进程可能持有 thread 的 writer 文件锁，续聊报 `already has an active writer`。修复要求等待原生进程及受管进程组实际退出后才释放运行时资源，并保留清理失败证据。

完整调查、实现、回归和发布哈希见 [原始记录](../research/codex-writer-cleanup-20261019.md)。已发布版本为 `0.5.7-dev.39.gc2e46c6.local.1792369800`。已有 21 个相关测试文件通过，包含真实文件锁、延迟退出、拒绝 TERM、子进程继承锁、启动失败、取消与同线程立即重试；这些是发布前证据，不冒充本次设备升级后的结果。

## 给用户的验收方式

1. Agent 先报告目标设备实际加载的版本及上述验证结果。
2. 回到曾报错的会话，发送一个无副作用的请求，例如“只回复已恢复，不继续执行此前任务”。
3. 确认正常得到答复，不出现 `already has an active writer`；确认要恢复原工作后再继续原任务。
4. 向 Agent 确认通过即可关闭。如仍失败，提供会话和大致时间，Agent 按新现场追查，不让用户自行处理锁文件。
