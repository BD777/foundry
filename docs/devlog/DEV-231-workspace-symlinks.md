# DEV-231 工作区文件树把软链接当成 4 KB 文件，点开报「requested workspace path is not a file」

状态：已部署 dev（train19-20261115：Server sha256 `1b046a1b…`，2026-11-15T09:58:04Z 起；Web `dc3d404bd630e0d6`，front matter 追加修复为 train20 的 Web `a4e4ae9349381109`；Worker `0.5.7-dev.358.g602765a0.local.1794735511`），部署后由 Agent 验证；待本人验收。未提交。

来源：本人截图（`.foundry/attachments/20261115/att_dmvo919u8v18_0_image.png`）。ByteWork 设置 →「工作区文件」→ 助理主目录（byte-dev，`/data00/home/dengcanwen/Foundry/personal-agent`）里，`.agents/skills/assistant-handoff`、`assistant-memory-and-list`、`assistant-projects`、`channel-0e47207b…` 显示为 4.0 KB 的文件，点开是「Couldn't read this file — requested workspace path is not a file」。编号说明：派单写的是 DEV-230，但 DEV-230 已被「定时回合删掉自己的 schedule」占用，本项用 DEV-231。

## 根因

- byte-dev 上实际情况（compute lease 只读查看）：`.agents/skills/*` 和 `.claude/skills/*` 都是软链接，指向 `../../.foundry/assistant-skills/<name>`，即**工作区内**的目录（DEV-196 的 `syncAssistantSkills` 这样建）。目标都存在。
- `packages/worker/src/session/files/workspace-files.ts` 的 `safeWorkspaceTreeListing` 用 `dirent.isDirectory()` 判断类型；对软链接它是 false，于是按文件列出，再 `statSync` 跟随链接取大小，得到目录的 4096 字节。Web 把它当文件去读，`workspaceFileForRead` 跟随链接发现是目录，报 "not a file"。
- 与派单的推测不同：这几个链接**没有**出工作区，`workspaceRealPath` 的越界拒绝不是这次的原因；它只是让「指向工作区外的链接」在别处表现为报错。

## 修复（对所有软链接通用）

Worker 按链接的去向分类，写进树条目的新字段 `link`（合约 `WorkspaceTreeEntry.link`/`readOnly`）：

| `link`      | 含义                                    | 列出                                                      | 打开                                                                       | 修改                                                                                                                                |
| ----------- | --------------------------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| （无）      | 普通文件/目录                           | 原样                                                      | 可                                                                         | 按原规则                                                                                                                            |
| `workspace` | 目标在工作区内                          | 按目标类型（目录可展开，文件带大小）                      | 跟随打开；读取结果带 `realPath`（目标在工作区内的真实路径）                | 按**目标**的规则：Server 对 `path` 和 `realPath` 都检查「Foundry 生成文件」，所以经链接打开 `.foundry/…` 也只读，保存/改名/删除被拒 |
| `foundry`   | Foundry 自己链进来的 skill 快照（见下） | 目录，可展开，条目 `readOnly`                             | 可读，读取结果 `readOnly: true`，助理设置里显示为 `foundry_skill` 只读说明 | 不可（Server 403；Worker 写入本来就拒绝越出工作区的路径）                                                                           |
| `outside`   | 指向工作区外                            | 不跟随：`isDirectory: false`，不报大小/扩展名，`readOnly` | 不读；Web 显示「指向工作区外的链接…Foundry 不会打开或修改」                | 不可                                                                                                                                |
| `missing`   | 目标不存在                              | 同上，不崩                                                | Web 显示「失效链接」                                                       | 不可                                                                                                                                |

**`foundry` 例外的判定（白名单按位置，不按名字）**：只有 `linkCodexSkills`（`skills/codex-native-skills.ts`）这一处把工作区外的东西链进工作区：每个选中的 skill 在 `<workspace>/.agents/skills/<name>` 建一个指向 `<state>/skill-sets/<setHash>/skills/<name>` 的链接，内容是校验过的快照，正是 Codex 加载的东西。所以判定要求同时满足：链接直接位于工作区内真实的 `.agents/skills` 目录下；它的真实路径在 `realpath(<state>/skill-sets)` 之内且不是该根本身；目标是含 `SKILL.md` 的目录；所读路径的真实位置在该 skill 目录之内（快照里再跳出去的链接仍拒绝）。指向 `skill-sets` 根、或放在别的目录里的同样链接都按 `outside` 处理，所以不能借此读到其他工作区的 skill 集合。`.claude/skills` 不在白名单里：Claude 走 plugin 目录，Foundry 不在那里链接工作区外的内容（助理 skill 的链接在工作区内，走 `workspace`）。

Web：

- `components/workspace/workspace-directory-browser.tsx`：链接名字后加文字标记（链接 / 链接的 skill / 工作区外 / 失效链接，不只靠图标或颜色），悬停标题说明去向；工作区外和失效链接用 `Link2Off` 图标。选择回调带上 `link`/`readOnly`。
- 助理设置「工作区文件」（`settings-files.tsx`）：工作区外/失效链接打开为说明卡片，不进入编辑器，没有编辑/保存/改名/删除按钮；`foundry_skill` 只读时编辑器也不显示改名/删除。
- 会话侧栏文件浏览（`chat-detail-panel.tsx`）：同样不去读工作区外/失效链接，显示说明。
