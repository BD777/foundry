# DEV-275 注释跟随正文：可滚动表格里的位置，展开表格同步显示与选中

2026-11-17。本人截图反馈：注释在可滚动的表格里位置错乱（高亮与编号停在原处，表格内容滚走）；希望用成熟的方式让注释跟着被注释的内容走，并在展开的表格里同步显示注释。

状态：远端检查见下；已部署 dev（2026-11-17）；Agent 代验收（2026-11-17，范围见各自验收记录）；已合入 main（PR #274）。

## 根因

DEV-266 的高亮和编号是叠加层：渲染后一次性测出选区矩形，用绝对定位画在回答外层。表格有自己的滚动区（横向、`max-h-[300px]` 纵向），它滚动时不触发重算，叠加层也不在滚动区里，所以错位。展开表格是 Dialog 里另一份 DOM，原实现只认回答本身的 DOM，所以展开后既看不到注释，也不能在里面选中注释。

## 改动（apps/web）

- 高亮改用浏览器原生的 CSS Custom Highlight API（`CSS.highlights` + `::highlight(answer-annotation)`，样式在 `styles/foundation.css`）：由浏览器直接画在文字上，随任何滚动容器移动，表头吸顶时照常盖住它；不再测量矩形。
- 编号标记与「注释」按钮用 Floating UI（`@floating-ui/react-dom`，Radix 自身的定位引擎，新增为直接依赖）锚定在文字范围末尾：`autoUpdate` 跟随文字与页面之间的每个滚动容器，`hide` 中间件在文字滚出可见区时隐藏标记。
- 「表面」抽象：注释始终用回答的偏移；回答本身和展开表格各自把偏移映射到自己的 DOM。展开表格按「行、列、单元格内偏移」与回答里的同一张表互相映射（`tableMirrorSurface`），所以展开后同步显示高亮与编号，在展开表格里选中也会建同一条注释（落在回答里同一位置）。
- 偏移 ↔ DOM 的映射独立成纯模块 `annotation-surfaces.ts`（无 React/UI 依赖）。顺带修了原有的边界错误：注释起点恰好落在两个文本节点之间时，旧代码把它放到前一个节点末尾（例如紧接表格之后的一段会被算成「从表格最后一格开始」）；现在起点归后一个节点、终点归前一个节点。
- `markdown-blocks.tsx`：展开表格包在 `AnnotationMirror` 里；不在可注释回答里时原样渲染。
- `scripts/audit-inline-styles.mjs`：例外理由更新为 Floating UI 算出的位置经作用域 CSS 变量传入。

## 验收步骤（dev）

1. 在任一会话里让 Agent 回一张宽表（列多到需要横向滚动、行多到需要纵向滚动）。
2. 选中表格某格里的文字 →「注释」→ 写评论 ✓：编号出现在所选文字末尾。横向、纵向滚动表格：编号与文字一起移动，滚出表格可见区时隐藏。
3. 点表格右上的展开：展开视图里同一处有同一编号；在展开视图里选中另一格文字加注释，关掉展开视图，回答里的表格上同一处出现新编号。
4. 发送后：两处都显示已发送注释的高亮，滚动时高亮贴着文字。浅色、深色、窄屏各看一遍。
