# DEV-180 · 对话中的原图已删除提示

## 问题

对话引用的本机图片被删除后，页面仍把它显示成通用加载错误，并给出“重试图片”按钮。原图已经不存在，重试不会恢复；红色错误样式和多行说明还会让连续多张失效图片占满回答区域。

## 调查

图片读取已经区分 `missing`、`removed`、`offline`、`slow` 和 `unavailable`。旧的 `LocalImage` 却把所有失败合成一个 Alert，只在正文里翻译具体原因。Markdown 图片外层也只根据“是否失败”处理间距和 caption，没有区分不可恢复的缺失与可重试的设备错误。

## 修复

- 将 `missing` 与 `removed` 归为终态缺失：显示“原始图片已删除”、文件名和可展开的完整路径，不再自动请求或提供重试按钮。
- 保留 `offline`、`slow`、`unavailable` 的可重试状态，但改为轻量状态行，明确“图片加载失败”和具体原因。
- 为缺失状态增加独立的 `data-image-state="missing"`，Markdown 在缺失时收紧上下间距并隐藏重复的图片 caption。
- 英文和简体中文文案同步改为原图已删除；测试覆盖缺失、离线重试、导出回退和慢读缓存。

## 限制

- “已删除”只能表示图片读取返回 `missing` 或记录已清理；如果设备离线，页面不会猜测文件是否仍存在，而是继续显示可重试的离线状态。
- 历史记录中的原图不会因此恢复或迁移。

## 验收步骤与预期结果

1. 在回答中插入一张图片，确认可正常显示；删除该图片后刷新对话。
2. 原图位置应显示“原始图片已删除”、文件名和展开箭头；展开后显示完整路径，且没有重试按钮。
3. 让设备离线后再读取另一张图片：应显示“图片加载失败”和离线原因，并保留“重试图片”按钮。
4. 在窄屏连续放置多张已删除图片：占位应保持紧凑，不重复显示 Markdown alt caption，也不出现横向溢出。
