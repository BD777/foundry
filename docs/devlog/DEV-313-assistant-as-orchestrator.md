# DEV-313 助理定位为编排者：调研等实际工作交给项目，助理只调度、判断、跟进

[事项索引](README.md) · 承接 [DEV-321](DEV-321-pa-eval-online-fixtures.md) 的 PA 路由评测 · 仅改助理角色文字（`personalagent/prompt/system.md` 及 prompt 版本与测试），不涉及新工具或接口

状态：**已部署 dev（train 105，Server only）；待本人验收**。

## 问题

助理原先的定位是「你想做什么，我弄清楚，决定放在哪里，自己做完」。实际运行中，助理经常自己回答调研、分析类问题，或在没有明确项目时直接追问，很少把有自己文件和跟踪的工作派发给项目里的 helper。

2026-11-19 本人决定：助理是编排者。它判断、派发、跟进、评判结果；调研、分析、写作、代码等实际工作在项目里由 helper 完成；关于本人自己世界的问题（清单、进行中的事、helper 报告了什么、聊天和邮件）仍由助理直接回答。这是本人的决定，不是 Agent 自行调整的范围。

## 改动

- **角色（`system.md`「What you are for」）**：助理是编排者，负责判断、派发、跟进、评判、告知；工作本身在项目里由 helper 完成。
- **第 3 步「问题」**：本人自己世界的问题直接回答；需要调研或调查的问题是工作，走第 2 步派发。
- **第 2 步「工作放哪里」**：调研归入本人的调研项目；没有调研项目时新建一个。派发是一份简报加一个 helper（`create_session`，或 `send_message` 给已有的 helper）。助理跟进，读证据后评判，并告知本人；在工具证实前，说明这是 helper 的说法。
- 删除「小事自己做」：原先的「做小事自己完成」「一次性的小事自己做」与新定位冲突，已删去。
- **版本**：`prompt.Version` 由 `2026-11-17.2` 改为 `2026-11-19.1`；`prompt_test` 的版本摘要与 `agentsFileBudget`（9500 → 10400 字节，新增约 860 字节）同步更新；两份 golden（`agents_full.golden`、`agents_new_person.golden`）重新生成。
- 不改变工具、协议、数据库或 Worker。

### 局限

- **每侧只跑一遍**。两个 95% 区间有重叠（对照上限 59.0，新提示下限 56.5），正确率的提升只能说明方向，不能当作已确认的统计结论。单个用例的变化也不是结论。
- **错误派发与错误创建增加**：错误派发率 0.111 → 0.143，新项目精确率 1.000 → 0.917。
- **4 个用例原来对、现在错**（对照正确、新提示错误）：`real-226a286f`、`real-51fb5d03`、`real-5212c8bc`、`real-df4b4b96`。其中 `real-226a286f` 与 `real-df4b4b96` 原先是提问、现在派发或回答错误；`real-51fb5d03` 原先派发正确、现在创建错误；`real-5212c8bc` 原先提问正确、现在回答错误。

## 验收步骤（本人）

1. 在助理聊天中提一个需要调研的请求（例如「帮我调研某个主题」）。预期：助理说明工作放入调研项目，并派发一个 helper；它不会自己直接写一份调研答复。
2. 问助理「我的清单里现在有什么」或「某个 helper 报告了什么」。预期：助理直接回答，不派发。
3. 对派发的结果，助理应读取证据后再告知；如果 helper 只是声称完成，助理应说明这是 helper 的说法。
