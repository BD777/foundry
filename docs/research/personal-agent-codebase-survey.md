# Personal Agent — codebase survey (Foundry, 2026-10-15)

Summary: Foundry already gives an orchestrating agent the session tools (create_session, send_message, wait_session, handoff_session, read_context, list_*) across every workspace the person is in, at most as Member. It cannot create/register/rename/configure/remove workspaces: no MCP tools, the session-token route allowlist blocks the REST routes, and agentScope never grants device ownership. No workspace brief exists (WorkspaceProjection.ContextSummary is a dead column). No per-user special workspace and no workspace-free entry; a Feishu DM paired to one workspace already works as an inbox. Summaries can be kept fresh via server-side session observers (server.go:211); an agent's SSE stream is pinned to one workspace.

## 1. What already exists

- Roadmap intent (README "Personal Agent（未开始）", CONTEXT.md): the Personal Agent is itself a Workspace holding an index of other Workspaces with progressive disclosure; Dispatch + fast response only; dispatch suggestions confirmed; creating a workspace is a change the person accepts; never a second source of truth. Prerequisites: entry not bound to a workspace, per-workspace brief, agent tools to create/register workspaces, personal-vs-workspace memory boundary. Diagram node: docs/assets/architecture.mmd:5.
- Workspace model: an existing folder on one device. Identity `.foundry/workspace.json` (packages/worker/src/workspaces.ts readWorkspace/initWorkspace); device registry `<state>/workspaces.json`. Server: apps/server/internal/store/workspaces.go WorkspaceProjection (ID, Name, LocalPath, Baseline, ContextSummary, AcceptedCount, ResolvedCount, DeviceID, AccessRole, UnavailableOnDevice); schema sqlitestore/schema.go:24; saveWorkspace in sqlitestore.go.
- Routes (httpapi/routes.go:303-330, workspaces_http.go): GET /api/workspaces; POST /api/workspaces {deviceId,path} (device owner; hub.SetupWorkspace 60s); POST /api/workspaces/subdirectories (device owner); PATCH /api/workspaces/{id} (Owner, name only); DELETE /api/workspaces/{id} (Owner; refused while busy; never deletes files; store.DeleteWorkspace + hub.ForgetWorkspace); relink + relink-suggestions (Owner); PUT …/skills, …/skills/{id}/pin, …/skill-bundles (Maintainer); PUT …/external-accounts (Maintainer); …/feishu* (Maintainer); …/members* (Owner); GET/POST …/inspection (git state only, workspace-inspection.ts); GET/PUT /api/me/default-skills. No per-workspace default profile; profiles are per device (PUT /api/devices/{deviceId}/profiles, device owner).
- Worker messages (packages/protocol/src/daemon-messages.ts): setup_workspace, forget_workspace, inspect_workspace, relink_workspace, find_moved_workspace; handlers packages/worker/src/daemon/handlers/workspaces.ts. setup_workspace → existingWorkspaceFolder (rejects missing folders) → initWorkspace + prepareForIssues; only CLI `init` mkdirs.
- MCP tools (httpapi/mcp_tools.json; dispatch mcp.go:257-283): list_workspaces (mcp_workspaces.go), list_resources, list_profiles, list_models, create_session (workspaceId/profileId/attachments/wait/issueId/verification/forkSessionId; mcp_sessions.go), send_message, wait_session (≤600000 ms), handoff_session, cancel_session, rename_session, list_sessions/list_group_sessions, get_session, read_context (summary/events/thread/transcript/subagents/changes/file/background; mcp_inspect.go, mcp_outputs.go), list_issues/get_issue, acquire/operate/release_resource, resource_status (compute = remote commands, on by default), feishu_events, ask_person (Issue executor only). Role filter: mcp.go mcpToolAllowed. `foundry` CLI = client of these tools.
- Session tools/skills/notes: per-turn HTTP MCP with fresh token (session-policy.ts buildClaudeLaunchPlan/foundryToolsEndpoint; Codex runner/codex-options.ts). System prompt append: session-policy.ts claudeSessionOptions(managed, deviceNotes) → systemPrompt.append; notes from sessionDeviceNotes → resource-pool.ts sessionResourceNotes + foundrySessionNote + sessionExternalAccountNote; Codex gets them as developer_instructions. Skills: httpapi/default_skills.go resolveWorkspaceSkills/sessionSkillRefs + skills.go withBuiltinSkills; skill-materializer.ts; skill-isolation.ts. Built-in `foundry` skill packages/worker/skills/foundry/ == apps/server/internal/builtinskills/foundry/ byte for byte (packages/worker/test/foundry-skill.test.mjs; revision in builtinskills.go:46-47). Env: FOUNDRY_SERVER_URL, FOUNDRY_SESSION_ID, FOUNDRY_SESSION_SOURCE, FOUNDRY_WORKSPACE_ID, FOUNDRY_SESSION_TOKEN (session-ambient.ts, profiles.ts sessionEnvironment()).
- Orchestration limits: sqlitestore/session_lineage.go:28-29 depth 4, 8 active children per parent; parent cancel doesn't cancel children; lineage is a record not a permission; children in another workspace don't join the parent's chat group. No per-actor rate limit.
- Feishu DM: feishu/ws_manager.go handleMessage (/pair → thread reply → unrouted dropped → new topic → CreateSessionAndDispatch). p2p route needs no @mention; feishu_bot_routes kind p2p bound to one workspace and bound_user_id (pairing.go boundUser, re-checked per message). ## 2. Gaps

1. Create a folder/repo and register it: no MCP tool; POST /api/workspaces not in agentRouteAllowed (policy.go:21); agentScope (access.go:148) never fills `owned` → requireDeviceOwner fails; setup_workspace rejects missing folders. Need create_workspace {deviceId, path, create?, gitInit?} with an explicit "acts as device owner" rule (+ confirmation per Roadmap).
2. Change settings: name/skills/bundles/external accounts/Feishu/members need Maintainer/Owner; agents capped at Member; no MCP tools. Profiles per device, not per workspace.
3. Archive/remove: Owner-only DELETE; no archive state; removal deletes chats/sessions/Issues server-side.
4. Summary of every workspace: no brief; ContextSummary legacy (only seed fills it; worker sends "" at issues.ts:482); list_workspaces returns names only; inspection = git metadata. Need brief field + update API/tool + a compact cross-workspace digest tool (recent sessions/Issues per workspace).
5. Workspace-free entry: everything requires workspaceId (routes.go:78, mcp.go:342, chat_layout.go, UI active-workspace model).
6. Per-user special workspace + identity: nothing on store.User (store/accounts.go:30) or workspace model; agent identity = session creator.
7. Session-token reach: all the person's workspaces as ≤Member; cannot create/rename/delete/relink workspaces, set skills/connectors/Feishu/members, Accept/Abandon/confirm/verify others' Issues, control others' sessions, call routes outside agentRouteAllowed, or stream SSE beyond one workspace (browser_events.go handleEvents pins reach.workspace). Devices visible only via list_resources. Fix point: agentScope + agentRouteAllowed + mcp_tools.json.
8. Freshness: no outbound hooks to agents. Options: session-end/Issue-update observer at server.go:211 marking briefs stale or writing digests, or Personal Agent timer polling. Feishu card state is in-memory only.

## 3. Constraints

- Provider access: inference only via Claude Agent SDK/CLI or Codex SDK/CLI; never /messages, /responses, /chat/completions; no provider health probes with stored credentials; /models catalog is the only exception → any summarizer is a Foundry session (like internal/chattitle).
- UI (AGENTS.md): one page per object; Workspaces page (/locations) adds/renames/removes (row menu, explicit destructive copy); Switch is the only action changing location; browsing never changes the active location; commit only after success; use components/ui primitives; features don't import each other or app/; new pages via navigation.ts/App.tsx…; i18n en + zh-CN.
- Server: every route needs an access rule (auth_coverage_test.go); multi-table writes via sqlitestore/tx.go; rebuild protocol after edits; keep the foundry skill identical in both places; the skill states facts, tool usage lives in tool descriptions.
- Product: Personal Agent is a workspace, never a second source of truth; dispatch confirmable; separation of duties (agent tokens can't confirm/verify/Accept); Chats aren't sandboxed. Docs: update module doc implementation boundary, README Roadmap (both languages), architecture.mmd.
