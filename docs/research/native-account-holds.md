# 官方账号停用记忆与手动恢复

2026-10-16。实现的是 Foundry 的派发阻止状态，不是主动在线健康探测，不发模型请求验证账号。

- 原生 Claude 明确报告 `account_on_hold` 时，按设备、运行时、账号标识持久记忆停用。Worker 注册、登录检查和服务重启不能覆盖它。
- Server 派发时保存输入对应的账号身份。迟到错误记到当时的账号，不能停用后来换上的账号；同一个输入不允许在重派时悄悄换号。缺少账号身份时不猜测归属。
- 普通模型回答、工具输出、401/403、限流或网络故障不产生停用。原生 assistant API error 使用结构化错误码；原生失败结果/子任务失败兼容明确的 `Your account is on hold` 加 `(error type account_on_hold)`。旧 Worker 的终态错误也兼容这个明确格式。
- 新会话选择器隐藏停用账号；已有会话保留原选择但禁用。Server 同时检查普通派发和 steer，不能靠 API 绕过。设备账号页保留状态、观察时间和“恢复使用”。
- 恢复只清除 Foundry 的阻止，不宣称官方恢复。仅设备所有者可操作，Agent 的 session token 不可操作；按钮绑定当前 hold ID，过期页面不能清掉新记录。
- 每个输入的停用信号只记一次。手动恢复后重复投递旧信号不会重新停用；新输入再次报停用会生成新的 hold ID。
- 状态保存在独立 SQLite 表，未改变账号凭据或登录配置。恢复时间保留在持久记录里。恢复不会主动重跑失败任务。
